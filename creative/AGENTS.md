# JJIntern creative work

These instructions apply to `creative/`. They do not replace application instructions elsewhere.

1. Start with [README.md](README.md), [current owner creative direction](CREATIVE-DIRECTION.md), then [product/brief.md](product/brief.md). Load only the playbook needed for the deliverable. Use the latest accepted reference and corrections; earlier revision briefs and approval gates are historical when superseded.
2. Check each product claim against evidence. This workspace initially contained no application source. Public marketing copy, illustrative UI and tested product behaviour have different evidential weight. Never convert one into another.
3. Read [brand/guide.md](brand/guide.md) and use [brand/tokens.json](brand/tokens.json). Keep observed identity separate from proposed marketing treatments. Use actual captures; do not invent screens, employers, testimonials or salaries.
4. Develop distinct ideas and select one before animation polish. Use [playbooks/directions.md](playbooks/directions.md) and [playbooks/concept-selection.md](playbooks/concept-selection.md).
5. Every hook must resolve. Every movement must reveal, connect, compare or demonstrate. Authored editorial graphics and real product demonstrations are both valid; a metaphor never verifies a product action. A succession of zoomed cards is an unfinished idea.
6. Keep evidence in [claims/ledger.json](claims/ledger.json); protect private data and record asset provenance. No avatars, voiceover or generated people by default.
7. Review with [qa/rubric.md](qa/rubric.md). Separate concept readiness, asset readiness and release readiness. Scores never predict views.
8. Finish reversible local work. Publishing, production-data changes and spending are outside this system's authorization.

Project skills live in `../.agents/skills/`; discovery and explicit invocation are documented in [playbooks/skills.md](playbooks/skills.md).
